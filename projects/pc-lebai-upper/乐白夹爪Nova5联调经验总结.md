# DOBOT Nova 5 × 乐白 LMG-90 夹爪 Modbus RTU 联调经验总结

> 本文档记录 2026-08 在 DOBOT Nova 5 上通过末端航插 RS485 驱动乐白 LMG-90 电动夹爪的完整调试过程、踩坑记录与最终结论，供后续正式流程开发参考。

---

## 一、任务目标

用 Nova 5 控制器直接驱动挂在末端航插上的乐白 LMG-90 夹爪（Modbus RTU 从站），替代原有的"USB-485 + 电脑 + 外置 24V"方案，实现机械臂脚本内直接控制夹爪开合。

**夹爪关键参数：**
- 供电 24V DC
- RS485 @ 115200 8N1，Modbus RTU 从站，地址 1
- 上电约 5 秒后自动"找行程"

**Nova 5 末端航插引脚（8 针）：**

| 引脚 | 定义 |
|------|------|
| 1 | 485B |
| 2 | 485A |
| 3 | DI_2 |
| 4 | DI_1 |
| 5 | 24V 输出 |
| 6 | DO_2 |
| 7 | DO_1 |
| 8 | GND |

## 二、最终结论（正确方案）

**根因：驱动末端工具 485 必须通过控制器"本地桥接服务"，而不是直接建主站或连对外网口。**

正确调用链：

```lua
SetTool485(115200, "N", 1, 1)                       -- ① 配置末端485: 115200 8N1
Wait(100)
local err, id = ModbusCreate('127.0.0.1', 60000, 1, true)  -- ② 连控制器本地桥, isRTU=true
if err == 0 then
    SetHoldRegs(id, 40001, 1, {50}, "U16")          -- 力度 50%
    SetHoldRegs(id, 40000, 1, {100}, "U16")         -- 幅度 100，张开
    local ok, pos = GetHoldRegs(id, 40005, 1, "U16")-- 读当前位置
end
```

**乐白寄存器表（地址直接用原始协议地址，无需偏移）：**

| 寄存器 | 含义 | 读写 |
|--------|------|------|
| 40000 | 幅度控制 | 可写 |
| 40001 | 力度控制 | 可写 |
| 40005 | 当前位置 | 只读 |
| 40006 | 当前力矩 | 只读 |
| 40007 | 指令是否执行完 | 只读 |
| 40008 | 找行程指令 | 可写 |
| 40010 | 开合速度 | 读写 |
| 40091 | 夹爪地址 | 读写 |

## 三、通讯架构（上位机 / 控制器 / 末端航插 / 夹爪）

```
PC(DobotStudioPro) ──TCP(192.168.5.1:6001)/USB──▶ Nova控制器
                                                      │
                                          ┌───────────▼──────────┐
                                          │ Lua脚本运行时(板载)     │
                                          │  SetTool485 /          │
                                          │  ModbusCreate /        │
                                          │  SetHoldRegs /         │
                                          └───────────┬──────────┘
                                          ModbusCreate连本地回环
                                          ┌───────────▼──────────┐
                                          │ 本地桥接服务           │
                                          │ 127.0.0.1:60000      │
                                          │ Modbus TCP→RTU 转换   │
                                          └───────────┬──────────┘
                                          ┌───────────▼──────────┐
                                          │ 工具485收发器         │
                                          │ 115200 8N1           │
                                          └───────────┬──────────┘
                                          末端航插 pin1/pin2/pin5/pin8
                                                      ▼
                                          ┌─────────────────────┐
                                          │ 乐白 LMG-90 从站 地址1│
                                          └─────────────────────┘
```

**关键认知：**
1. **脚本在控制器内部运行**（不在电脑上），所以 `127.0.0.1` 指控制器自己。
2. **上位机不直接和夹爪通讯**，只负责编辑/上传脚本、看日志。
3. **本地桥接服务（127.0.0.1:60000）** 是通往末端 485 的唯一正确通道，做 TCP→RTU 转换。
4. **夹爪是总线上唯一从站**，物理上通过航插 485 + 24V 连接。

## 四、踩坑记录与改正（完整复盘）

| # | 错误 | 现象 | 原因 | 改正 |
|---|------|------|------|------|
| 1 | `Sleep()` 延时 | "未声明 Sleep" | Nova 脚本无 Sleep | 用 `Wait(ms)` |
| 2 | `ReadHoldRegs` 函数名 | "未声明" | 函数名记错 | 正确为 `GetHoldRegs` |
| 3 | 力度写 `'F64'` 类型 | 写错数据 | 参数类型错误 | 应为 `'U16'` |
| 4 | `ModbusCreate` 句柄存 `id` 却判断 `mb_id` | 永远"创建失败" | `mb_id` 从未赋值 | `mb_id = id` |
| 5 | `WriteSingleHoldReg` 写死 `{100}` | 写什么都=100 | 未用传入值 | 用真实 val |
| 6 | `isRTU` 传整数 `1` | "paramter4 类型不兼容" | 固件要求**布尔** | 用 `true`（文档写 int，固件不一致）|
| 7 | `ModbusRTUCreate` 直连 | create=0、写入-1(超时)、末端485零字节 | 它走的是**控制柜485**，不是末端工具485 | 改走本地桥 `ModbusCreate` |
| 8 | `ModbusCreate('192.168.5.1',503,...)` | create=0、写入瞬间-1 | 503 是对外网口上的**其他服务**，不是 RTU 桥 | 用 `127.0.0.1:60000` |
| 9 | 未调 `SetToolPower(1)` | 夹爪可能无电 | 文档要求先使能末端电源 | 脚本开头加 `SetToolPower(1)` |
| 10 | TCP 接口 `ModbusCreate` 的 isRTU 传布尔 `true` | 报错 `-50001` | TCP 接口（ASCII）isRTU 要**整数 1**，板载 Lua 才要布尔 `true` | TCP 接口用 `1` |

**最耗时、最核心的坑（#7、#8）：**
- `ModbusRTUCreate` 文档写"创建基于 RS485 接口的 Modbus 主站"，但实际挂在控制柜 485 口（手册标注"暂未开放"），不驱动末端工具 485。
- `ModbusCreate('192.168.5.1',503)` 的"创建成功"只代表 TCP 握手成功，不代表数据通道可用——503 上的服务不是 Modbus 桥，请求被瞬间拒绝。
- 正确路径是控制器**本地回环** `127.0.0.1:60000`，这个服务外部设备访问不到，只有控制器内脚本能连。

## 五、排查方法论（可复用经验）

1. **先隔离再猜**：用 USB-485 + 外置 24V 直连夹爪，按协议原样发标准帧。
   - 全部应答 → 夹爪、协议、地址、波特率都没问题 → 故障圈定在机器人侧。
   - 关键帧验证：写幅度 `01 10 9C 40 00 01 02 00 64 F5 72` → 回 `01 10 9C 40 00 01 2E 4D`。
2. **交换 485A/B**：排除极性因素（30 秒）。
3. **PC 当 Modbus 从站监听总线**：挂工具 485 上监听，机器人狂写 N 次仍零字节 → 铁证该通道没往末端 485 发数据。
4. **"创建成功"≠"通讯通"**：TCP 能连上不代表请求被正确转发，必须看实际寄存器读写返回值。
5. **文档 ≠ 固件**：参数类型（isRTU）、返回值顺序都可能和文档不一致，以固件/IDE 提示和实测为准。

## 八、最终正确脚本骨架（可直接用于正式流程）

```lua
-- 初始化
SetToolPower(1)                              -- 使能末端电源
Wait(200)
SetTool485(115200, "N", 1, 1)                -- 末端485 115200 8N1
Wait(100)
local err, id = ModbusCreate('127.0.0.1', 60000, 1, true)
if err ~= 0 then
    print("Modbus 创建失败", err)
    return
end

-- 找行程（若未找行程：读40009==1 则写40008=1）
local need = GetHoldRegs(id, 40009, 1, "U16")
if need == 1 then
    SetHoldRegs(id, 40008, 1, {1}, "U16")    -- 触发找行程
end

-- 控制
SetHoldRegs(id, 40010, 1, {80}, "U16")       -- 速度
SetHoldRegs(id, 40001, 1, {50}, "U16")       -- 力度
SetHoldRegs(id, 40000, 1, {100}, "U16")      -- 幅度（100张开/0夹紧）

-- 反馈
local pos  = GetHoldRegs(id, 40005, 1, "U16")
local done = GetHoldRegs(id, 40007, 1, "U16")

ModbusClose(id)
```

## 九、PC 上位机开发（TCP 二次开发接口，已验证）

正式产线方案：PC 上位机直接通过 Nova 的 TCP 接口控制夹爪，无需依赖板载脚本。

**连接与协议：**
- Dashboard 端口 **29999**：上位机下发控制指令
- 实时反馈端口 **30004/30005/30006**：机器人/状态反馈
- 消息格式（ASCII 文本）：下发 `指令(参数)`，应答 `ErrorID,{返回值},指令(参数);`

**TCP 接口 与 板载 Lua 的差异（重要坑）：**

| 项目 | 板载 Lua 脚本 | PC TCP 接口 |
|------|--------------|-------------|
| `ModbusCreate` 的 isRTU | 布尔 `true` | **整数 `1`** |
| 参数类型错误码 | -1 通用 | `-50001` = 第 1 个可选参数类型错误 |

**实测流程（PC → Nova → 本地桥 → 工具485 → 夹爪，已验证）：**
```text
下发: SetTool485(115200,N,1,1)              → 0,{}
下发: ModbusCreate(127.0.0.1,60000,1,1)     → 0,{0}      index=0
下发: GetHoldRegs(0,40005,1,U16)            → 0,{100}    当前位置
下发: SetHoldRegs(0,40001,1,{50},U16)       → 0,{}       力度
下发: SetHoldRegs(0,40000,1,{100},U16)      → 0,{}       幅度(张开)
```

**上位机工程位置：** `C:\Users\2\Documents\Default Project\pc_lebai_upper\`
- `nova_client.py`：TCP(29999) 通讯层，命令封装/应答解析
- `gripper.py`：夹爪控制服务层（init/开合/力度/速度/状态/找行程）
- `main.py`：CLI 入口（`--selftest` / `--open` / `--close` / `--position` / `--force` / `--speed` / `--find-stroke` / `--status`）
- 已实机验证：`--selftest` 读取、`--open` 张开、`--close` 闭合全部正常
- 通讯层仅用 Python 标准库，零第三方依赖
